- Codex/中转兼容渠道非流式兜底失败时会额外记录 curl 错误、stderr 和上游前 4KB 响应体，方便排查中转站尺寸不支持、余额不足、分组无渠道或内部错误；日志不会记录 API Key。

- Codex/中转兼容渠道流式图片解析改为优先等待 `image_generation.completed` 最终图片，`partial_image` 只在上游断流且没有 completed 时作为兜底，避免 2K/4K 大图提前返回半成品导致画面发糊；已用 VIP 渠道实测 `2048x2048` 和 `3840x2160` 都会返回 completed。
- Codex/中转兼容渠道的 curl 请求绑定前端请求上下文，客户端或 Next 代理断开时会停止上游 curl 并记录 context done；同时记录 partial/completed 事件和 curl completed 日志，方便排查 4K 长请求外层 504 但后端无错误日志的问题。

- Codex/中转兼容渠道如果先收到 `partial_image` 后又收到上游错误事件，将不再把 partial 半成品当成功结果返回，避免 4K 生成断流时前端显示模糊半成品；后端会继续走非流式兜底或返回真实错误。
- Codex/中转兼容渠道对 4K/大图增加最多 4 次流式自动重试：遇到上游断流（含 `stream disconnected before completion`）、流式协议错误、EOF、连接重置或超时时会优先重新等待 completed 最终图，单次 curl 最长等待 30 分钟，并记录每次尝试耗时；4K 可重试流式错误耗尽后会跳过成功率较低的非流式兜底，直接提示“4K 生成中断，未返回最终图片，请稍后重试”，避免继续等待无效兜底。
- Codex/中转兼容渠道的 4K 流式解析不再把只有 `partial_image`、没有 completed 的结果当成功返回；如果上游只返回预览图就结束，会按可重试错误重新发起流式请求，避免前端显示模糊半成品。
